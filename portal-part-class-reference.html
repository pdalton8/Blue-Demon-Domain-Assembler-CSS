Blue Demon Domain: part class reference

A simple guide to placing and styling Slate parts.

Enter class names without dots, separated by spaces. Visual reference: bdd-mockup-master.html.

The master uses the older assembler. This guide describes the current Global Assets and Assembler. Markdown version.

Navigation is detected from .portal-navbar inside the part; no Slate placement class is required. portal-slot--navigation is optional. The Assembler extracts the inner navbar and hides its original wrapper, keeping navigation outside the content cards. Do not add portal-navbar to the Slate wrapper.

Global Assets styles the native address dialog for desktop and full-viewport mobile use. Its Save/Cancel handlers and fw_lazy_commit target stay intact. During an address save, a temporary refresh wrapper recognizes the exact native parent.FW.Refresh(); response in the same-origin address commit iframe, closes the active address dialog, and announces the update. Other refresh calls retain Slate behavior. Cancellation, dialog removal, unconfirmed responses, and a two-minute timeout restore the original function; unconfirmed saves never close the dialog or show success. Verify authenticated persistence in Slate after deployment.

Above or below the checklist: use portal-slot--status and place the part before or after the checklist in Slate. There are no dedicated above/below-checklist classes.

Use portal-ignore on code-only parts that the Assembler must not move, group, or add classes to. Global Assets applies display: none !important to remove their visual footprint while leaving the nodes in place. Ordinary scripts still execute; code relying on visible layout measurements, and embedded content such as iframes, may behave differently while hidden. It overrides placement classes and automatic checklist routing; descendant parts are also excluded from discovery. Unlike portal-raw, it skips assembly rather than just presentation. It does not isolate global CSS or other scripts. Set it on the original Slate part before page initialization; deploy both the updated Assembler and Global Assets.

Visit and search are self-contained parts inside the main layout's left column, alongside the right rail on desktop. Use portal-slot--visit and portal-slot--search, without portal-action-card. Their existing feature-container and portal-search HTML supplies their appearance; slot classes do not generate content or a form. Parts are moved intact without extra headings or card wrappers. All visit parts follow the main sections, then all search parts, preserving Slate order within each slot. Add hide-empty if needed.

Within Student resources only, parts with portal-copy are placed before other resource parts, regardless of Slate's delivered order. Source order is preserved within the copy group and within the remaining resource parts. Other sections are unchanged.

More information is the final section in the left content column, below visit and search, alongside the right rail on desktop. Its empty-section hiding and late-content recovery still apply.

Section order: Enrollment path, Payments and activities, Scholarships, Direct Admit, Supplemental materials, Future Forward, Honors program, Auditions, Student housing, Application messages, Student resources, More information. Eyebrow labels match these group names. Sections with no parts are omitted; sections containing only empty or hidden parts are hidden and reappear when visible text, media, or controls load. Part nodes are preserved.

Application messages groups the portal-slot--attention, portal-slot--ribbon, and portal-slot--updates parts. Parts with no recognized placement go to More information. The above-hero portal-ribbon-part is unchanged. Enrollment-path routing uses portal-slot--status, not portal-section--status.

The Assembler moves each portal-slot--footer part after the assembled page content and excludes it from More information. It does not generate a footer; the Slate part is the footer. Set the part's classes to portal-slot--footer portal-raw to avoid a card surface. The footer template reproduces the links shown in the current DePaul University website footer; verify destinations and labels before publishing if the official footer changes.

Checklist widgets are automatically routed to status. Legacy portal-slot--application-checklist and portal-slot--next-steps-checklist are replaced with portal-slot--status.

2. Appearance: Slate CSS Classes field

portal-raw preserves the part's HTML and inline styles and skips assembler-added presentation classes, including the automatic right-rail card. Use it with a placement class, instead of message tones, action cards, or custom notices. Page-wide typography and section layout still apply; it does not isolate CSS or remove styles authored inside the HTML.

Message tones style a plain h1/h2/h3 and body content directly in the part or inside its content div. No base message or heading class is required.

All message cards are compact everywhere, including alongside the checklist. Placement does not change message density.

For the decision widget, use portal-slot--status decision-update without a message tone or action-card class. The callout appears when a heading or link is present. Empty parts (including a single empty div) are hidden without removing them, so late widget content can still appear.

The custom notice classes require their supplied HTML. Do not combine them with a generic tone or action-card class: that can create nested card surfaces.

Add hide-empty to any assembled portal part or element to hide it when empty, including whitespace, empty wrappers, or helper-only content. Visible text, media, or controls restore it as content loads. For example: submission-conf hide-empty. The assembler manages portal-empty; do not add that class manually. Existing Slate visibility settings are preserved.

portal-accordion opens the first available panel once by default, including late-loaded widgets. Users can close it normally without it reopening automatically; other panels retain their existing state.

For copy beneath the Enrollment path eyebrow, use portal-slot--status portal-copy on a part containing paragraphs, before the checklist/messages in Slate's part order. For a separate heading, use portal-slot--status portal-heading on a part containing an appropriate heading element, such as <h2>Your next steps</h2>. These classes also work in other slots. They style existing content without inserting text or changing semantics. The heading uses the style guide's h3 visual size, preserving your chosen HTML heading level. Do not combine with card or message-tone classes.

Application-message cards slide sideways on hover. Action/opportunity cards lift with a shadow, except the resource list has no outer card or lift. Resource links darken with a blue border and slide 2px on hover; opportunity images zoom. Motion is disabled for visitors requesting reduced motion.

Routing only places content. Unlike the old master assembler, the current assembler does not add card, heading, or button appearance classes inside content.
